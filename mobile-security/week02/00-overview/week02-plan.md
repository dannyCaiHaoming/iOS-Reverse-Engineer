# 第 2 周执行计划：业务代码审计与 LLDB 调用链

总投入：12 小时。建议拆成 6 个学习单元，每次 1.5-2.5 小时。

## 本周能力目标

本周不以“学会多少条 LLDB 命令”为目标。真正的目标是完成这一条证据链：

```text
业务入口
  -> 本地会话与权限状态
  -> 客户端策略判断
  -> 请求构造
  -> 服务端授权模拟
  -> 结果消费
```

你需要能够在源码审计和动态调试之间来回切换：源码给出候选路径，LLDB验证实际运行路径；动态调用栈暴露真实调用者，再回到源码解释数据与边界。

## 单元 1：业务资产、状态机和信任边界，2 小时

学习：

- 阅读 Lesson 01。
- 运行 Demo 的三个场景，先只记录行为，不阅读所有实现。
- 列出核心资产：会话 token、用户身份、角色、会员状态、目标资源 owner、导出结果。
- 画出“登录 -> 本地准入 -> 请求 -> 服务端授权 -> 返回”的状态机。

实操：

- 完成 `business-flow-map-template.md`。
- 为每条安全判断标注最终可信来源：客户端缓存、请求参数或服务端会话。

验收问题：

- 哪个字段只影响 UI/客户端流程？
- 哪个字段若被服务端信任会形成真实授权风险？
- 攻击者需要什么前置能力？

## 单元 2：源码辅助的逆向方法，2 小时

学习：

- 阅读 Lesson 02。
- 不从文件第一行顺序阅读；从 `main` 的场景入口、输出结果和安全相关命名建立候选路径。
- 识别数据生产者、转换者、消费者和最终授权者。

实操：

- 为 `SessionSnapshot.role`、`isPremium`、`requestedOwnerID` 和 `bearerToken` 分别画一条简化数据流。
- 提出 3 个动态验证假设，并写出每个假设的观察点和证伪条件。

产出：业务调用链初稿和动态验证计划。

## 单元 3：LLDB 基础证据，2.5 小时

学习：

- 阅读 Lesson 03 和本地命令手册。
- 掌握 target/process/thread/frame 四层模型。
- 使用符号正则断点，而不是依赖固定行号。

实操：

- 在 `baseline` 场景定位 `exportReport`、本地策略和服务端授权。
- 每个断点记录 `bt`、`frame variable`、关键表达式结果和继续执行后的最终输出。
- 至少做一次条件断点或断点命令自动记录。

产出：`lldb-call-chain-evidence.md` 前半部分。

## 单元 4：对照场景与风险边界，2 小时

实操：

- 调试 `local-tamper`：本地角色/会员字段被修改，但安全服务端拒绝跨用户导出。
- 调试 `server-trusts-client`：不安全服务端信任客户端声明，导致跨用户导出成功。
- 比较两个场景的客户端调用链是否相同、服务端分支在哪里不同。

要求：

- 写出“已证明”和“未证明”。
- 不能只截图最终 `allowed/denied`；必须记录授权函数收到的身份、owner 和客户端声明。

产出：LLDB 证据后半部分和风险边界表。

## 单元 5：隐藏源码后的盲定位，2 小时

学习：

- 阅读 Lesson 04 和 Lab 02。
- 暂时关闭源码文件，只使用命令行行为、LLDB 符号搜索、断点命中和调用栈。

实操：

- 在 75 分钟内重新找到入口、本地策略和服务端授权三个位置。
- 记录至少一个错误入口、排除理由和调整过程。
- 时间到后再回看源码校准。

产出：`blind-analysis-log.md`。

## 单元 6：修复、测试、报告与面试，1.5 小时

学习：

- 阅读 Lesson 05。
- 选择服务端错误信任客户端声明的问题进行修复。

实操：

- 修改 Demo，使不安全模式也不得仅凭客户端 role/premium 声明授权资源。
- 增加或调整测试，证明跨用户请求被拒绝、合法同用户请求仍成功。
- 完成迷你审计报告和 10 分钟面试讲解。

## 时间失控时的删减顺序

可以删减：

- 重复执行 baseline 场景。
- 美化图表和截图。
- 额外 LLDB 命令探索。

不能删减：

- 两个对照场景。
- 调用栈和变量证据。
- 隐藏源码分析。
- 修复与回归测试。
- 结论边界和面试口述。

## 本周过关定义

你不需要在一周后自称“会 iOS 逆向”，但必须可以准确地说：

> 我能从业务资产和入口建立候选调用链，使用 LLDB 在 Swift 业务模块中验证实际调用栈、对象状态和授权分支，并能区分客户端本地策略被修改与服务端授权失守。隐藏源码后，我仍能通过符号、断点和运行行为重新定位关键路径。
