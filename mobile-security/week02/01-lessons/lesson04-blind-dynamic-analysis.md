# Lesson 04：隐藏源码后的动态定位

建议用时：60 分钟讲义 + 75 分钟限时实验。

## 1. 为什么第 2 周就做盲定位

有源码时，人会不自觉依赖文件名、行号和实现顺序。真正的逆向需要在信息不完整时做决策。第 2 周的盲定位保留 Debug 符号，但要求关闭源码，训练从“知道实现”过渡到“通过行为和符号重新发现实现”。

它不是完整无符号逆向。第 3 周才会加入 Mach-O、字符串交叉引用和反汇编。

## 2. 75 分钟分析流程

### 0-10 分钟：建立行为差分

只运行三个场景，记录：

- 输入参数；
- outcome/reason；
- 哪些 trace 相同，哪些不同；
- 最可能的共同入口和分叉点。

不要先猜漏洞名称。

### 10-20 分钟：模块和符号侦察

```lldb
target modules list
image list
image lookup -rn 'export|Export|authorize|policy|Policy|session|Session'
```

建立候选符号表，并写选择理由。搜索结果多时按“业务入口 -> 决策 -> 敏感操作”排序。

### 20-45 分钟：验证共同调用链

在 `baseline` 上设置 2-4 个断点。每次命中记录：

- 当前函数；
- 直接调用者；
- 关键参数；
- 后续应继续追踪的函数。

目标不是恢复所有代码，而是找到最短安全相关路径。

### 45-65 分钟：差分两个风险场景

分别运行 `local-tamper` 和 `server-trusts-client`：

- 哪些函数两者都经过？
- 服务端在哪个函数分叉？
- 同一个 token、owner、client claims 的组合如何被不同模式处理？
- 哪条证据支持“本地绕过未造成服务端越权”？
- 哪条证据支持“错误服务端模式造成越权”？

### 65-75 分钟：结论与未知项

输出：

- 已定位调用链；
- 已证明事实；
- 未证明事实；
- 一个被排除的错误假设；
- 第 3 周需要通过静态二进制分析补足的信息。

## 3. 入口排序算法

候选函数按四个维度评分，每项 0-2：

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 与敏感资产距离 | 无关 | 间接 | 直接读写/决策 |
| 可控输入 | 无 | 不确定 | 明确接受用户/客户端数据 |
| 分支价值 | 无判断 | 状态转换 | 权限/资源/安全判断 |
| 动态可观察性 | 难命中 | 可命中但噪声大 | 场景稳定命中 |

优先调试总分高的函数。这个简单模型可以避免在低价值 Runtime 符号里迷路。

## 4. 如何处理错误入口

错误入口不是失败，只要留下排除记录：

```text
候选：MemorySessionStore.currentSession
选择理由：session 可能是权限来源
观察：三个场景都会命中，只返回缓存对象，不做资源判断
结论：保留为数据来源证据，但不是最终授权点
下一步：追踪调用者 SensitiveActionCoordinator 和 MockExportAPI
```

面试官很看重这类记录，因为陌生样本分析不可能每次第一步都正确。

## 5. 信息层级

盲定位时按可靠性排序：

1. 实际运行结果和稳定复现。
2. 断点命中、调用栈和变量值。
3. 符号名称、字符串和模块边界。
4. 依据常见架构做出的猜测。

低层级线索可以指导下一步，但不能覆盖高层级反证。

## 6. 何时停止深挖

企业分析不是无限逆向。达到以下条件可在本周停止：

- 已找到敏感入口、客户端策略和服务端授权模拟点；
- 已解释 token、owner 和 claims 的传播；
- 已比较安全/错误模式的关键分支；
- 已形成可修复、可复测的根因结论。

无需恢复标准库、打印所有对象字段或理解每一个编译器 thunk。

## 7. 陌生 iOS 样本迁移

真实 IPA 中可能没有 Debug 符号。届时入口会变成：

- ObjC class/selector 元数据；
- Swift 残留符号或类型描述；
- 用户可见字符串和交叉引用；
- 网络、Keychain、WebView、Crypto 等导入 API；
- 行为触发后的动态调用栈；
- 函数地址与 ARM64 控制流。

第 2 周的业务模型仍然适用，只是证据获取方式更困难。

## 8. 面试自测

- 有 Debug 符号的盲定位为什么还不能称为完整逆向？
- 搜索到 50 个 `authorize` 相关符号，如何排序？
- 你如何记录一个失败路径，使其成为有效证据？
- 什么时候应该停止恢复代码，转向风险判断和修复？
- 如果动态调用栈看不到业务上游，你会如何调整？
