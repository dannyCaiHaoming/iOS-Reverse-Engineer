# 第 1 周讲师验收标准

本周的目标不是“做出了几个页面”，而是证明你能把一个移动端现象组织成审计证据。总分 100，70 分通过，85 分以上优秀。

| 项目 | 分值 | 高分标准 |
| --- | ---: | --- |
| 安全模型与攻击面 | 15 | 能解释平台机制、资产、入口、信任边界与服务端边界 |
| Demo 实操 | 15 | 4 个 Lab 可运行，实验基线可复现 |
| 证据与结论边界 | 15 | 至少两条发现具备线索、运行证据、已证明与未证明 |
| 审计报告 | 25 | 风险、影响前提、修复、复测与误报条件完整 |
| 面试表达 | 15 | 能在两分钟内讲清项目、证据和后续路线 |
| 就业转化 | 15 | 能将本周成果写成移动安全岗位语言 |

## 1. 安全模型与攻击面，15 分

- 0-5 分：只能背概念，把 Keychain 说成绝对安全，或把客户端绕过直接等同于服务端漏洞。
- 6-10 分：能解释沙盒、权限、Keychain、ATS、URL Scheme、WebView，并完成攻击面地图。
- 11-15 分：能说明资产、攻击者能力、信任边界与服务端确认项，知道哪些检查可在后续工具化。

## 2. Demo 实操，15 分

- 0-5 分：Demo 未运行，或只能复制代码而无法解释实验目的。
- 6-10 分：四个实验入口可操作，记录了基本运行结果。
- 11-15 分：每个实验有风险假设、可复现步骤和局限说明，能作为 Week 2 静态审计对象。

## 3. 证据与结论边界，15 分

- 0-5 分：把代码或配置线索直接报为高危，证据无法复现。
- 6-10 分：至少两条发现有环境、步骤和运行证据，能区分本地行为与推测的业务影响。
- 11-15 分：静态/配置线索与运行证据相互印证；每条写清已证明、未证明和待服务端确认内容。

## 4. 审计报告，25 分

- 0-10 分：只有笔记，没有风险条目或复现步骤。
- 11-18 分：至少两条风险有影响、验证、修复和复测，等级不过度夸大。
- 19-25 分：报告含风险前提、误报条件、责任方和可执行复测；客户端与服务端边界清晰。

## 5. 面试表达，15 分

- 0-6 分：回答像背概念，使用“破解 App”“绝对安全”等表达。
- 7-11 分：能回答基础问题，能讲清 Demo 的攻击面与一个风险闭环。
- 12-15 分：能主动说明 Demo 证明了什么、还不能证明什么，并把 Week 2 静态审计和后续逆向路线讲清。

## 6. 就业转化，15 分

- 0-5 分：学习内容不能转成简历或作品材料。
- 6-10 分：能写出项目经历草稿，说明与移动安全岗位的关系。
- 11-15 分：能使用岗位语言：

```text
构建 iOS Security Lab 教学实验 App，覆盖本地存储、Keychain、URL Scheme、WKWebView/JSBridge 等基础攻击面；以风险假设、静态/运行证据、影响边界、修复和复测输出小型审计报告，为后续 IPA 静态分析、LLDB/Frida 动态分析和 Mobile App Inspector 规则沉淀建立基线。
```

## 必须返工

- Demo 没有运行。
- 没有审计报告或证据日志。
- 不能解释 UserDefaults 与 Keychain 的边界。
- 不能解释 URL Scheme 为什么属于外部输入边界。
- 把客户端现象直接写成服务端失守。
- 面试表达以“破解 App”为主线。
