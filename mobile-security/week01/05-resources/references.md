# 第 1 周本地必修讲义：iOS 安全模型与攻击面

本文件就是第 1 周需要读的资料，不需要跳转到外部网站。建议用 90 分钟完成：每节读完后，能回答“它保护什么、它不保护什么、审计时看哪里”。

## 1. iOS 安全模型：先理解边界，不背名词

iOS 安全由几层共同构成：设备和系统保护、应用签名与沙盒、数据保护、权限控制、网络传输。审计不是检查“有没有一个安全 API”，而是判断某项资产在这些层之间经过时是否被正确保护。

你本周只需要记住这句话：

```text
平台机制提供默认边界；App 实现决定资产怎样流动；服务端决定认证和授权是否真正成立。
```

因此，客户端把 `isVIP` 显示为 `true` 只能证明本地展示或本地流程可变，不能证明服务端已经把权益给了未授权用户。

## 2. 沙盒与本地数据：它保护谁，何时不够

每个 App 有独立容器。常见位置包括 `Documents`、`Library/Application Support`、`Library/Preferences`、`Library/Caches` 和 `tmp`。正常 App 之间不能任意读取彼此容器；但审计仍要检查敏感数据是否进入普通文件、缓存、日志、截图、备份或共享容器。

本周结论：沙盒不是“数据天然安全”。它限制普通跨 App 访问，但不能替代数据最小化、加密/访问控制、备份排除、日志脱敏和服务端 token 治理。

审计问题：

- token、手机号、证件、定位、会话信息是否落入普通文件、偏好、缓存或日志？
- 数据是否会被备份、共享、展示在后台快照或通知中？
- 这些数据是否真的需要持久保存？

## 3. Keychain：优先存凭据，不等于绝对安全

Keychain 适合 token、refresh token、密码和密钥引用。它比 `UserDefaults` 更适合敏感凭据，因为使用系统提供的受保护凭据存储和访问控制模型。

但面试不能说“用了 Keychain 就安全”。还要看：

- 可访问时机：锁屏后、首次解锁后还是始终可用？
- 是否允许迁移/恢复，是否和备份策略一致？
- 是否通过 Keychain access group 与其他 App/Extension 共享？
- 凭据是否有过期、撤销、轮换和设备/用户绑定？

本周 Lab 的正确表达：`UserDefaults` 写入 token 是敏感凭据落入普通偏好存储的教学风险；Keychain 是更合适的客户端存储选择，但服务端仍必须验证 token 的有效性和权限。

## 4. 代码签名与权限：签名不是业务授权

代码签名帮助系统验证 App 来源与完整性，Entitlements 表示签名授权的能力，例如 Keychain group、App group、Associated Domains、推送和 iCloud。权限用途说明告诉用户 App 为什么请求相机、定位等敏感能力。

审计要点：

- 权限和能力是否最小化，是否与实际功能和隐私声明一致？
- 共享能力涉及哪些 App 或 Extension，是否扩大了数据边界？
- 签名和客户端完整性不能替代服务端对用户、订单、角色和设备状态的授权判断。

## 5. ATS 与网络：配置是线索，流量才是事实

ATS 推动 iOS App 使用合适的 TLS 传输。`Info.plist` 中的全局放宽或特定域名例外值得审计，但仅看到例外不等于漏洞。

审计顺序：先记录例外范围，再确认 Release 是否存在、真实请求是否经过该路径、数据是否敏感、是否有其他证书校验或服务端控制。第 1 周不做抓包和证书绑定深挖，只需要学会不夸大配置线索。

## 6. URL Scheme、WebView 与外部输入

自定义 URL Scheme、Universal Link、WebView URL、JavaScript message 都可能把外部数据带进 Native 业务。它们不是天然漏洞，风险由输入校验、来源约束、允许动作和服务端授权共同决定。

本周必须掌握：

- 不在 URL 中传递长期 token、密码或其他敏感凭据。
- Scheme 路径、参数格式、跳转目标和状态必须白名单或严格校验。
- WebView 只加载受控内容；JSBridge 方法最小化；敏感动作由 Native 和服务端二次确认。
- 客户端收到一个参数，不等于服务端会接受该参数完成敏感业务。

## 7. 用六类问题组织攻击面

不需要背编号，先按下面六类提问：

| 分类 | 本周的核心问题 |
| --- | --- |
| Storage | 敏感数据在哪里落地、缓存、日志或备份？ |
| Auth | 本地 token 或状态是否被错误当作最终授权？ |
| Network | ATS、TLS 和请求路径是否保护数据？ |
| Platform | URL Scheme、权限、WebView、剪贴板如何处理外部输入？ |
| Privacy | 权限、SDK、敏感 API 和数据用途是否一致、最小必要？ |
| Resilience | 客户端保护能增加成本，但不能成为唯一业务边界。 |

## 8. 本周必须能回答的五个问题

1. 为什么 Keychain 不等于绝对安全？
2. 为什么 `UserDefaults` 命中只是线索，仍需看数据类型和运行路径？
3. 为什么 URL Scheme 是外部输入边界？
4. 为什么 WebView/JSBridge 要同时看来源、参数和敏感动作？
5. 为什么客户端修改不能直接推出服务端已经失守？
