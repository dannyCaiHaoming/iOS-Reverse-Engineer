# 半年训练营总纲：移动安全与逆向工程求职出班计划

周期：24 周，每周约 12 小时。

目标岗位：iOS/移动安全工程师、应用安全工程师、安全开发工程师、SDL 安全工程师、隐私安全工程师。

目标结果：面向广州市场，争取月薪 25k 左右、年包 30w+ 的岗位。

执行状态（2026-07-22）：第 1 周已完成，按“基础校准周”计入。第 2 周已按本总纲重建为“业务代码审计与 LLDB 调用链追踪”，旧版工程配置课程已删除。

## 最重要的调整

旧版把有实质内容的逆向训练放到第 5 周以后，节奏偏慢，也没有充分利用用户已有的 iOS 开发和 Web 渗透经验。新版从第 2 周立即进入业务代码、调用链和动态调试，第 4 周必须完成第一次陌生授权 iOS 样本分析。

这里的“有用逆向”必须同时满足五项标准：

1. 面对没有现成步骤的授权样本，能自行选择入口。
2. 能定位关键业务或安全逻辑，而不只是搜索字符串。
3. 能解释至少一条调用链或关键数据流。
4. 能使用静态证据和 LLDB/Frida 动态证据相互验证。
5. 能说明结论边界、真实风险、防护建议和服务端确认项。

因此，学习进度不是“到第几周开始装逆向工具”，而是：

| 时间点 | 能力里程碑 | 是否属于有用逆向 |
| --- | --- | --- |
| 第 2 周结束 | 能在有源码 Demo 中用 LLDB 跟踪一条业务调用链，观察参数、状态和返回值 | 逆向过渡能力 |
| 第 3 周结束 | 能从 Mach-O、ObjC 元数据、Swift 符号和反汇编中定位关键函数 | 已进入真实二进制分析 |
| 第 4 周结束 | 能对首次接触的授权 iOS 样本完成静态定位、动态验证、调用链说明和结论边界 | 第一份有用逆向成果 |
| 第 8 周结束 | 能读基础 ARM64，并完成 iOS 与 Android/JNI 跨层分析 | 面试基础线 |
| 第 12 周结束 | 能用 LLDB/Frida 追踪业务数据流，并判断客户端与 API 安全边界 | 企业场景可用线 |
| 第 16 周结束 | 能验证反调试、Hook 检测、完整性和证书绑定等防护的效果与局限 | 中高级能力线 |
| 第 20 周结束 | 有 7 个结构化样本、综合审计报告和可现场讲解的证据包 | 作品集投递线 |

以当前第 1 周已完成计算：第 2 周立即开始有效训练，约 3 周、36 小时后必须拿出第一份陌生样本逆向报告。若第 4 周仍只能跟教程改返回值，课程判定失败并调整，不继续堆新工具。

## 培养定位

职业主线固定为：

> iOS 开发背景 + 移动端逆向分析 + App 安全审计 + Mobile API/业务安全 + 隐私合规 + SDL 工具化。

这不是漏洞题速成班，也不是只学 Frida 脚本。25k+ 岗位需要两组相互印证的证据：

```text
逆向硬实力：陌生样本 -> 静态定位 -> 动态验证 -> 调用链/数据流解释
企业交付力：攻击面 -> 风险判断 -> 修复/复测 -> 自动化或 SDL 闭环
```

训练材料只使用自建 Demo、开源靶场、公开 Crackme 或明确授权目标，不分析未授权商业 App，不以绕支付、绕授权或修改商业功能作为成果。

## 时间投入规则

每周 12 小时按阶段分配，逆向不再等到第 5 周：

- 第 2-4 周：每周至少 6 小时用于业务代码定位、LLDB、Mach-O 和陌生样本分析。
- 第 5-12 周：每周至少 7 小时用于 ARM64、iOS/Android 静态分析、LLDB/Frida 和数据流追踪。
- 第 13-16 周：每周至少 5 小时用于网络信任链、防护机制和防护验证逆向。
- 第 17-20 周：每周至少 4 小时用于陌生授权目标和逆向证据包，其余时间完成工具与审计交付。
- 第 21-24 周：每周至少 2 小时保持现场二进制分析和项目讲解手感。

单纯安装环境、复制命令、照答案得到 flag、只改函数返回值，均不计入上述逆向时数。工程配置审计在第 2 周压缩为 1 小时，并从第 3 周开始逐步交给扫描脚本。

## 出班能力画像

半年后应能做到：

1. 对陌生 IPA/APK 建立攻击面和分析优先级。
2. 分析 IPA、Mach-O、ObjC Runtime 元数据、Swift 符号以及基础 ARM64 控制流。
3. 使用 LLDB 和 Frida 定位关键逻辑、观察参数/返回值、追踪调用链和数据流。
4. 掌握 Android APK/DEX/Smali、JNI/ELF/ARM64 和基础 Frida，达到移动安全岗位最低可用线。
5. 判断本地鉴权、敏感数据、URL Scheme/Deep Link、WebView、网络信任链和客户端防护风险。
6. 把客户端现象区分为本地可绕过、真实客户端风险、需要服务端确认的业务风险。
7. 评估 token 生命周期、越权、重放、设备绑定和参数篡改等 Mobile API 风险。
8. 验证证书绑定、反调试、越狱/Root 检测、Hook 检测、完整性校验的效果与边界。
9. 把隐私 Manifest、SDK、权限、敏感 API 和数据流审计转成技术检测能力。
10. 基于 OWASP MASVS/MASTG 输出正式报告，并能完成修复建议、复测和 SDL 闭环。
11. 把高频检查沉淀为 `Mobile App Inspector`、检查表和 CI 安全卡点。
12. 在 90 分钟内对首次接触的授权样本形成有证据、有边界的初步结论。

## 24 周逐周课程地图

### 第一阶段：iOS 业务分析与首次陌生样本（第 1-4 周）

#### 第 1 周：基础校准与证据方法（已完成）

- 定位：确认 iOS 安全基础和攻击面意识，不作为硬实力证明。
- 内容：沙盒、本地存储、Keychain、URL Scheme、WebView、风险报告基本结构。
- 产出：基础 Demo、攻击面清单、第一份迷你报告。
- 限制：不再用更多周重复概念和工程配置。

#### 第 2 周：业务代码审计与 LLDB 调用链追踪

- 核心问题：一个客户端“登录/会员/敏感操作”状态是如何产生、传播、消费的？
- 知识：业务状态机、资产与信任边界、Swift/ObjC 调用关系、断点策略、调用栈、寄存器与参数、条件断点、内存与对象观察。
- 实验：在有源码 `iOS Security Lab` 中，从 UI 入口跟到业务判断、数据访问和网络请求边界；随后隐藏部分源码再次定位。
- 时间：业务建模 2 小时，代码审计 2 小时，LLDB 4 小时，盲审 2 小时，报告/口述 1 小时，配置快扫 1 小时。
- 产出：`business-flow-map.md`、`lldb-call-chain-evidence.md`、10 分钟面试讲解稿。
- 验收：不能只在已知行号下断点；必须说明为什么选择入口、调用方是谁、观察到了什么、结论不能证明什么。

#### 第 3 周：Mach-O、ObjC/Swift 元数据与反汇编定位

- 核心问题：没有源码时，如何从二进制恢复程序结构并找到值得分析的函数？
- 知识：IPA/App Bundle、Mach-O Header/Load Commands/Segments/Sections、代码签名位置、ObjC 类/方法元数据、Swift 名字改编、导入符号、字符串交叉引用、ARM64 函数边界和基础分支。
- 工具：`file`、`otool`、`nm`、`strings`、`codesign`、`plutil`、Ghidra 或 Hopper。
- 实验：对自建 Release 包做无源码侦察，从字符串、类名、选择子、导入 API 或数据引用定位两条候选路径，再用反汇编排除错误入口。
- 产出：`binary-recon-report.md`、Mach-O 结构图、候选函数选择与排除记录、Inspector 二进制元数据扫描雏形。
- 验收：能从“某个函数看起来可疑”推进到“谁调用它、它依赖什么数据、下一步应在哪里动态验证”。

#### 第 4 周：首次陌生授权 iOS 样本分析

- 核心问题：面对没看过源码、没有固定步骤的样本，能否独立建立分析路径？
- 内容：限时攻击面建立、入口排序、静态证据、LLDB 动态验证、调用链/数据流、假设证伪、风险边界。
- 实验：一个公开 Crackme/靶场或由课程提供的授权 iOS 样本；先不看源码和答案完成 120 分钟分析，再复盘遗漏。
- 产出：`reverse-evidence-pack/sample-01-ios/`，包含完整报告、关键截图/命令证据、调用链、误报排除、修复或防护建议、面试讲解稿。
- 阶段答辩：15 分钟现场讲解，随机追问入口选择、动态证据和服务端边界。
- 阶段门槛：这是第一份“有用逆向”成果。低于 70 分则补练，不进入 ARM64/JNI 阶段。

### 第二阶段：ARM64、iOS 深化与 Android 跨层基础（第 5-8 周）

#### 第 5 周：ARM64 与编译器视角

- 知识：寄存器角色、AAPCS64 参数/返回值、栈帧、`bl`/`ret`、条件分支、加载存储、常见比较、数组/结构体访问、优化带来的源码差异。
- 实验：从 C/ObjC/Swift 小函数的源码、汇编和运行时状态建立对应关系；手工解释一个校验函数的控制流。
- 产出：ARM64 速查表、函数分析记录、控制流图。

#### 第 6 周：iOS Runtime 深入与低符号场景

- 知识：`objc_msgSend`、selector/class/method lookup、block、delegate/closure 回调、Swift/ObjC 桥接、符号缺失下的字符串/API/调用者反推。
- 实验：LLDB Runtime 枚举、断点命令、调用者回溯；分析第二个 iOS 样本。
- 产出：`sample-02-ios-runtime/`、LLDB 命令脚本和运行时证据。

#### 第 7 周：Android APK、DEX、Java/Smali 业务逻辑

- 知识：APK、Manifest、DEX、组件、Intent/Deep Link、WebView、Jadx 伪代码、Smali 寄存器与调用指令、基础混淆识别。
- 实验：从组件入口跟踪到一条业务判断和敏感数据路径，不以修改返回值作为结束。
- 产出：`sample-03-android-smali/`、Android 攻击面地图。

#### 第 8 周：JNI、ELF 与 Android ARM64 跨层分析

- 知识：Java/JNI 注册、`JNI_OnLoad`、动态/静态绑定、ELF 符号与段、参数跨层转换、native 调用链。
- 实验：从 Java 调用点定位 JNI/native 函数，用静态和动态证据解释一条跨层校验或数据处理链。
- 产出：`sample-04-android-jni/`、Android Mini Lab v0.1、第二次阶段答辩。
- 阶段门槛：能比较 iOS ObjC/Swift 与 Android Java/JNI 的分析入口、证据类型和困难点。

### 第三阶段：Frida、业务数据流与 API 边界（第 9-12 周）

#### 第 9 周：iOS Frida 动态分析

- 知识：进程/模块/类枚举、ObjC 方法拦截、参数/返回值/对象观察、调用栈、脚本健壮性、Swift 定位策略。
- 实验：围绕一条已由静态分析定位的业务链设计观察点，动态确认调用时机和数据变化。
- 产出：可复用脚本、`sample-05-ios-frida/`，以及“脚本结果能证明什么”的证据说明。

#### 第 10 周：Android Frida、Java 与 JNI 联动

- 知识：Java overload、ClassLoader、native export/offset、参数序列化、线程和时机问题。
- 实验：从 Java 层追踪到 JNI 层并验证关键输入/输出。
- 产出：`sample-06-android-frida-jni/`、跨层动态分析报告。

#### 第 11 周：网络协议、数据处理链与密码学调用识别

- 知识：请求构造、token/签名/设备参数、序列化、编码与加密的区分、Keychain 到请求头的数据流、TLS 信任链和证书绑定入口。
- 实验：在受控 mock backend 中追踪“本地数据 -> 处理函数 -> 请求参数 -> 服务端校验”全链路。
- 产出：`mobile-api-security-lab.md`、端到端数据流图、客户端/服务端责任矩阵。

#### 第 12 周：90 分钟陌生样本与业务影响判断

- 内容：首次接触的 IPA 或 APK，限时完成攻击面、入口优先级、一个关键逻辑定位、动态验证计划和结论边界。
- 产出：`timed-sample-07/`、`unknown-sample-analysis-playbook.md` v1、服务端确认清单。
- 阶段答辩：现场复盘成功路径、无效路径、误报排除和时间分配。
- 阶段门槛：不能讲清调用链/数据流，或把客户端绕过直接等同于服务端失守，不得进入防护阶段。

### 第四阶段：网络信任、防护验证、隐私与 SDL（第 13-16 周）

#### 第 13 周：TLS、证书绑定与网络信任边界

- 内容：ATS、系统信任评估、证书绑定实现位置、Session delegate/网络库调用链、代理环境、失败回调和降级风险。
- 实验：在自建 Lab 中实现正确与错误的信任验证，静态定位并动态验证调用链。
- 产出：网络信任审计报告和修复/复测用例。

#### 第 14 周：反调试、越狱/Root 与 Hook 检测

- 内容：常见检测信号、组合策略、执行时机、误报、兼容性、绕过成本、客户端防护边界。
- 实验：先实现防护，再以授权评估者身份分析其入口、覆盖面和薄弱点。
- 产出：iOS/Android 防护验证样本、攻防对照表。

#### 第 15 周：完整性、混淆与防篡改验证

- 内容：代码/资源完整性、签名校验、控制流和字符串混淆识别、关键逻辑下沉、远端风控、完整性证明的边界。
- 实验：分析一个中等难度防护样本，记录失败路径和替代验证方式。
- 产出：`hardening-validation-report.md`、Evidence Pack 深度样本升级。

#### 第 16 周：隐私数据流、自动化与 Mobile SDL

- 内容：Privacy Manifest、第三方 SDK、权限/敏感 API、采集到传输的数据流、威胁建模、安全需求、CI 卡点、漏洞分级和复测指标。
- 实验：把至少 5 个高频检查点实现为 Inspector 规则或 CI 检查，并记录误报控制。
- 产出：`Mobile App Inspector v0.2`、`privacy-data-flow-map.md`、`mobile-sdl-playbook.md`、阶段答辩。

### 第五阶段：陌生目标综合审计与作品集（第 17-20 周）

#### 第 17 周：综合目标选择、范围与威胁模型

- 选取未提前阅读源码的开源/授权移动应用，确定资产、信任边界、测试范围和证据规范。
- 产出：审计计划、攻击面地图、风险假设清单。

#### 第 18 周：完整静态与动态审计

- 执行二进制侦察、关键路径定位、LLDB/Frida 验证、API 边界分析和误报排除。
- 产出：证据索引、问题草稿和复现材料。

#### 第 19 周：工具化、规则准确性与修复复测

- 完成 `Mobile App Inspector v1.0`，提供 IPA/APK 样例输出、规则解释、误报/漏报记录和测试。
- 对综合目标给出研发可执行修复方案与复测用例。

#### 第 20 周：正式报告与项目答辩

- 产出：`iOS Security Lab v1.0`、`Android Mini Lab v1.0`、`Mobile App Security Audit Report v1.0`、`Real Target Audit Report v1.0`、`Reverse Engineering Evidence Pack v1.0`。
- 答辩：20 分钟项目审计 + 10 分钟随机样本逆向深挖。
- 阶段门槛：7 个样本中至少 3 个中等以上难度、2 个陌生样本、3 个静态/动态双证据、2 个跨层调用或数据流。

### 第六阶段：求职转化与面试实战（第 21-24 周）

#### 第 21 周：广州 JD 聚类与简历改造

- 用真实 JD 对能力和作品做映射，形成移动安全、AppSec/SDL、隐私安全三版重点不同的简历。

#### 第 22 周：技术面与现场分析

- 完成 iOS/Android/ARM64/Frida/API/SDL/隐私题库；训练 30 分钟二进制走查和白板调用链讲解。

#### 第 23 周：模拟面试与投递反馈迭代

- 至少两轮技术模拟面试、一轮项目压力面；根据真实反馈修补证据，不盲目增加新知识。

#### 第 24 周：出班评估、谈薪与持续投递

- 完成项目答辩、技术面、HR/薪资面；输出岗位优先级、投递节奏和能力维护计划。

## 逆向证据包毕业门槛

毕业前必须完成 `Reverse Engineering Evidence Pack`：

1. 7 个结构化授权样本，至少 3 个中等以上难度，至少 2 个首次接触的陌生样本。
2. 至少覆盖 Android Java/Smali、Android JNI/ARM64、Android Frida、iOS ObjC/Swift 动态分析、iOS 防护验证。
3. 至少 3 个样本有静态和动态双证据，至少 2 个解释跨层调用或关键数据流。
4. 至少一次 90 分钟限时分析，明确已证明、未证明、误报排除和服务端确认项。
5. 每个样本都包含问题拆解、入口理由、静态证据、动态证据、调用链/数据流、替代路径、风险/防护意义、修复复测和面试稿。

不计入成果：复制脚本、只交 flag、只改返回值、复述现成题解、没有调用方和边界解释、未授权商业 App 分析。

## 每周教学与验收标准

每周材料必须包含本地教案、Demo/样本、练习、作业、评分表、报告模板、面试追问和讲师验收。外部链接只能作为出处和课后核验，不能代替本地教材。

每个实验形成两层闭环：

```text
未知样本 -> 入口假设 -> 静态定位 -> 动态验证/证伪 -> 调用链/数据流 -> 结论边界
攻击面 -> 风险判断 -> 影响 -> 修复 -> 复测 -> 自动化/SDL -> 面试表达
```

每周 100 分：

- 知识理解：15 分
- Demo 与动态实操：20 分
- 独立逆向与证据：25 分
- 风险/修复/复测：20 分
- 面试表达：10 分
- 工具化或就业转化：10 分

低于 70 分不进入下一周。逆向关键周（第 4、8、12、16、20 周）如果“独立逆向与证据”低于 18/25，即使总分及格也必须补考。

## 面试官验真标准

面试官不以“用过多少工具”判断深度，而会继续追问：

- 为什么从这个入口开始，而不是另一个入口？
- 没有符号、源码或固定脚本时怎么继续？
- 静态判断由哪条动态证据验证？
- 这个函数的调用者和下游消费者是谁？
- 数据在哪里产生、转换、存储、发送和校验？
- 你排除了哪些替代路径或误报？
- 客户端现象能否造成真实业务影响，服务端还需确认什么？
- 修复应该落在客户端、服务端还是研发流程，如何复测？
- 哪些步骤能自动化，自动化规则有哪些误报边界？

课程产出回答不了这些问题，就不算达到 Level 3，也不能写成“熟悉移动端逆向”。

## 出班表达

合格表达不是“做过若干 Crackme、会用 Frida”，而应是：

> 我的主线是 iOS 移动安全。我能在首次接触的授权 IPA 中，从 Mach-O、ObjC/Swift 元数据和导入 API 建立候选入口，使用 LLDB/Frida 验证调用链和关键数据流，并区分客户端现象、真实业务风险与服务端确认项。我也完成了 Android Java/Smali、JNI/ARM64 的跨层样本，把高频检查沉淀进 Mobile App Inspector 和 SDL 检查流程，并能输出基于 MASVS/MASTG 的修复与复测报告。
