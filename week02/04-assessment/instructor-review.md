# 第 2 周讲师验收

## 验收材料

讲师逐项检查：

- `business-flow-map.md`
- `lldb-call-chain-evidence.md`
- `blind-analysis-log.md`
- `week02-mini-audit-report.md`
- `week02-interview-pitch.md`
- Demo 修复 diff
- `swift run BusinessLogicLabChecks` 结果

缺少 LLDB 证据或 Demo 修复，不能只靠笔试通过。

## 第一关：知识口试，15 分钟

必须不看讲义回答：

1. 认证、授权、客户端准入分别是什么？
2. token、owner、role、premium 各自由谁产生、谁能控制、谁应当权威确认？
3. 为什么修改本地 premium 不能直接定为高危？
4. Debug 与 Release 对 LLDB 证据有什么影响？
5. `frame variable` 和 `po` 的证据风险有什么不同？

通过：五题至少四题准确，且不能混淆资源授权与身份认证。

## 第二关：证据复核，20 分钟

随机指定一个场景，要求：

- 复现入口断点。
- 给出当前调用栈。
- 指出调用者和后续授权位置。
- 展示至少三个安全相关字段。
- 说明这个场景已证明和未证明什么。

通过：操作可以有小错误，但分析顺序和结论必须正确。

## 第三关：盲分析复盘，10 分钟

讲师重点看：

- 是否真的有时间线，而不是事后补写。
- 是否保留错误入口和排除原因。
- 是否根据证据调整假设。
- 是否知道本周 Debug 符号降低了难度。

没有失败路径的“完美日志”反而需要追问真实性。

## 第四关：修复评审，15 分钟

修复必须满足：

- 服务端根据 token 找权威会话。
- owner 与主体匹配。
- entitlement 使用服务端值。
- baseline 保持成功。
- tamper 场景被拒绝。

以下修复不合格：

- 删除攻击场景。
- 客户端写死字段。
- 只做字符串混淆或反调试。
- 所有导出统一拒绝。

## 第五关：面试答辩，10 分钟

要求用“背景、方法、证据、边界、修复、复测”结构讲解。讲师至少追问两次：

- 你怎么知道？
- 还有其他解释吗？

候选人必须引用自己的证据，而不是回答“源码就是这样写的”。

## 最终判定

### 通过

- 总分至少 70。
- LLDB 动态证据至少 18/25。
- 风险边界至少 9/15。
- 所有硬性材料齐全。

### 补考

- 调用链有证据但结论夸大。
- 能调试但盲分析入口选择混乱。
- 修复正确但没有合法路径回归。

补考只重做薄弱项，不重复抄全部教案。

### 不通过

- 没有真实运行和断点证据。
- 隐瞒盲分析中查看源码。
- 把未授权第三方 App 作为练习对象。
- 无法区分客户端与服务端安全边界。

## 第 3 周准入能力

通过后，用户应能带着以下能力进入无源码静态分析：

- 从行为和资产提出入口假设。
- 通过动态调用栈校准静态候选图。
- 追踪安全字段到最终消费者。
- 记录错误路径和结论边界。

第 3 周不会再重复讲基础 LLDB 命令，而会直接把入口证据替换成 Mach-O、符号、字符串和反汇编。
