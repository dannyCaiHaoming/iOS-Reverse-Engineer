# Lesson 05：从动态现象到公司可用报告

建议用时：90 分钟。

## 1. 技术现象不是风险结论

本周会观察到这些现象：

- 本地缓存中的 role/premium 可以被实验代码修改。
- 客户端策略因此从拒绝变成放行。
- 请求携带被修改的 claims。
- 安全服务端模式仍拒绝跨用户资源。
- 错误服务端模式允许跨用户资源。

前四项是证据，第五项连同资产和前置条件才构成完整业务风险。报告必须把证据和推论分开。

## 2. 三层结论模型

### L1：本地现象

示例：客户端会员状态可在受控调试环境中修改，本地策略随后放行。

可以证明客户端字段不是安全边界。不能自动证明远程可利用或服务端数据泄露。

### L2：客户端可利用风险

示例：本地准入被绕过后，可使用仅存在于客户端的离线导出、解密、文件访问或敏感 SDK 能力。

即使服务端安全，也可能有真实客户端影响。需要证明敏感结果确实在设备上产生。

### L3：服务端/业务风险

示例：服务端使用客户端 claims 授权，并未根据 token 主体校验资源 owner，导致 Bob 获取 Alice 的报告。

需要服务端请求/响应、资源差异和授权逻辑证据。严重度通常高于单纯 UI 绕过。

## 3. 根因写法

弱写法：

> 客户端可以修改 premium，存在越权。

强写法：

> 导出接口把客户端提交的 role/premium 声明作为授权依据，且未校验 token 对应主体与 requestedOwnerID 的资源归属。攻击者控制自己设备上的本地状态后，可使服务端向 Bob 的有效会话返回 Alice 的报告。

强写法包含：错误信任源、缺失检查、主体、资源和结果。

## 4. 风险成立条件

每条报告都列出：

- 攻击者是否需要登录；
- 是否只需普通设备/代理修改请求，还是需要调试/高权限设备；
- 目标资源标识是否可猜测或获得；
- 服务端是否实际返回敏感内容；
- 是否存在速率限制、二次确认或审计告警；
- 影响是单用户、跨用户还是批量。

本 Demo 为本地模拟，不能宣称真实远程接口受到影响。报告标题应写“自建 Lab 的服务端授权错误信任客户端声明”，而不是泛化为某公司漏洞。

## 5. 修复责任分层

### 服务端必须修复

- 从 token/服务端 session 得到主体和权威角色。
- 服务端根据主体、动作、资源、环境独立授权。
- 不把客户端 role/premium/owner 声明作为决定性依据。
- 默认拒绝，拒绝原因不泄露不必要资源信息。
- 对高价值导出增加速率限制、审计和异常检测。

### 客户端可以改进

- 本地策略保留为体验优化，但命名和架构上避免误认为权威授权。
- 不在不必要的请求字段中发送安全敏感声明。
- 会话切换、登出、订阅变化时正确清理缓存。
- 对本地离线资产采用适当数据保护和完整性策略。

### SDL/流程改进

- API 设计评审必须列主体、资源和动作三元组。
- 测试用例覆盖 A 用户访问 B 用户资源。
- Code Review 禁止服务端直接信任客户端提交的角色/会员标记。
- 对高风险接口建立授权中间件和统一策略。

## 6. 复测矩阵

修复后至少测试：

| token 主体 | 请求 owner | 客户端 claims | 预期 |
| --- | --- | --- | --- |
| Alice | Alice | 正确 | 允许 |
| Bob | Alice | 伪造 analyst/premium | 拒绝 |
| Bob | Bob | 伪造 analyst/premium | 按服务端权威 entitlement 决定 |
| 无效 token | Alice | 任意 | 拒绝 |
| Alice | 不存在 owner | 正确 | 拒绝且不泄露资源存在性 |

只验证“攻击请求失败”不够，还要证明合法请求没有被修复破坏。

## 7. 证据质量

高质量动态证据包含：

```text
构建/版本：Debug，具体 commit 或文件哈希
启动参数：local-tamper / server-trusts-client
断点位置：完整符号或可复现搜索规则
调用链：入口到最终授权
关键值：token 主体、owner、role、premium
结果：允许/拒绝和可观察敏感结果
边界：自建模拟、没有真实网络、没有证明远程可利用
```

截图是辅助，文本日志和命令更利于复现。敏感 token 在真实报告中应脱敏。

## 8. 面试讲解结构

用 6-8 分钟讲一个发现：

1. 业务资产和场景，45 秒。
2. 候选调用链和入口选择，60 秒。
3. 静态发现，60 秒。
4. LLDB 动态证据，2 分钟。
5. 两个对照场景与结论边界，90 秒。
6. 根因、修复、复测，90 秒。
7. 可自动化与不可自动化部分，45 秒。

不要花三分钟背 LLDB 命令。面试官要听分析决策。

## 9. 可自动化部分

可以自动化：

- 特定高价值函数的断点命令与调用栈采集。
- 请求字段、owner/role/premium 的差分测试。
- 跨用户授权回归测试矩阵。
- 源码中危险授权模式的 SAST 线索。

难以完全自动化：

- 字段在真实业务中的权威语义。
- 敏感资源和攻击者模型。
- 客户端现象是否转化为可接受风险。
- 修复对业务体验和兼容性的影响。

## 10. 面试官追问

- 为什么客户端仍需要权限判断？
- 如果服务端完全安全，这个本地问题还要不要修？
- 你的 Demo 没有真实 HTTP，凭什么说明 API 风险？
- 如何避免修复越权后把合法业务阻断？
- 这个问题如何进入 SDL，而不是每次靠渗透发现？

回答边界：Demo 证明的是授权数据源和检查顺序的原理，以及分析方法的可复现性；不能冒充真实生产漏洞。求职价值来自能够还原调用链、判断边界并设计修复复测。
